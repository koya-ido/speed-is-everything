# バトルモード検証・テスト実行スキル (Battle Mode Verification)

Windows側のGoogle Chromeを DevTools MCP 経由で複数端末（タブ）として並行操作し、バトルモードの機能・リアルタイム同期・エッジケース・ライフサイクル・UI表示を網羅的に検証するためのガイドラインです。

## 1. 前提条件と環境セットアップ

本検証は WSL2 から Windows の Chrome リモートデバッグポート（`9235`）へアクセスして実施します。
基盤スキル: [.agents/skills/chrome-devtools-mcp/SKILL.md](file:///home/koya_ido/practice/speed-is-everything/.agents/skills/chrome-devtools-mcp/SKILL.md)

テスト内容に応じて、以下の役割ごとにタブを作成・管理します。

## 2. DevTools MCP によるバトルモード検証手順（マルチタブワークフロー）

リアルタイム対戦（WebSocket / Supabase Realtime）の機能検証を行う際は、以下のマルチタブ操作手順に従って進めます。

### ステップ 1: タブ1（Host / プレイヤーA）の準備と部屋作成

1. `list_pages` でタブ1の `pageId` を確認し、`navigate_page` で `http://localhost:3000/ja/battle`（またはトップページ）へアクセス。
2. `take_snapshot` で要素の `uid` を特定し、「部屋を作る (HOST)」ボタンを `click`。
3. 初期HP（500〜3000ms）と表示名を確認し、「部屋に参加する」ボタンを `click` して待機ロビーを作成。
4. ロビー画面で発行された6桁ルームコード（例: `344-861`）を `take_snapshot` から取得。

### ステップ 2: タブ2（Guest / プレイヤーB）の参加

1. `new_page`（または既存タブ2）で `http://localhost:3000/ja/battle?room={ROOM_CODE}&confirm=true` を開く。
2. `select_page` でタブ2を選択し、`take_snapshot` を実行。
3. プレイヤー名を入力・確認し、「部屋に参加する」ボタンを `click`。
4. プレイヤー2枠として正常にマッチング完了し、タブ1（Host）側にも即時反映されることを確認。

### ステップ 3: タブ3（Spectator / 観戦者A）の参加

1. `new_page`（または既存タブ3）で同一ルームURLを開く。
2. `select_page` でタブ3を選択し、「部屋に参加する」を `click`。
3. 自動的に `SPECTATOR` ロールが割り当てられ、「観戦・待機中: 1名」と表示されることを確認。全タブのヘッダー・アコーディオンに即座に同期されることを検証。

### ステップ 4: 20戦試行による対戦進行と同期検証

1. `select_page` でタブ1（Host）に切り替え、「バトル開始」ボタンを `click`。
2. 3タブ同時に `COUNTDOWN` → `WAITING` (赤) → `ACTION` (緑 / PUSH!) へ同期遷移することを確認。
3. `click` または `evaluate_script`（高速入力スニペット）でプレイヤー操作を実行。
4. ラウンド解決時のHP、ダメージ計算、コンボ倍率、勝敗判定が3画面すべてで完全同期（1msの差異もないこと）を確認。
5. 結果モーダル（`BattleMatchResultModal`）から「再戦する」または「ロビーに戻る」を押下し、連続して**計20戦**の試合を反復実施。同期ズレや表示不整合が発生しないかを徹底検証。

### ステップ 5: リロード離脱・自動昇格・部屋解散の検証

1. 試合中またはロビー待機中にタブ2（Guest）を `navigate_page` でリロードし、即時抜け判定＆試合即時決着（`opponent_left`）を検証。
2. タブ1（Host）がロビーに戻ると、待機していたタブ3（Spectator）が自動的にプレイヤー2へ昇格することを確認。
3. タブ1（Host）で「部屋を解散」を実行し、全タブで終了通知が表示されトップ/ロビーへ復帰することを検証。

## 3. DevTools MCP 検証ユーティリティ

### 3-1. 高速タップ / 狙ったタイムの擬似入力スニペット

DevTools MCPのリモート通信タイムラグ下でも、ランクボーナス（Godlike: <180ms, Excellent: <200ms）やフライング（赤画面タップ）を確実に再現するため、対象タブに対して `evaluate_script` で以下のスニペットを実行可能です。

```javascript
// 画面のアクション領域を擬似クリックする関数
(() => {
  const arenaButton =
    document.querySelector('button[aria-label="tap-area"]') ||
    document.querySelector("main") ||
    document.body;
  const event = new PointerEvent("pointerdown", {
    bubbles: true,
    cancelable: true,
  });
  arenaButton.dispatchEvent(event);
  return { clicked: true, timestamp: performance.now() };
})();
```

### 3-2. 3ロール横断 不正表示（undefined / null / NaN / 生キー）一括検出スニペット

全タブの各フェーズにおいて、以下のスクリプトを `evaluate_script` で実行し、不正な文字列がDOM上に露出していないかを一括検査します。

```javascript
(() => {
  const text = document.body.innerText;
  const patterns = [
    { name: "undefined", regex: /\bundefined\b/i },
    { name: "null", regex: /\bnull\b/i },
    { name: "NaN", regex: /\bNaN(ms)?\b/i },
    { name: "object_object", regex: /\[object Object\]/ },
    { name: "untranslated_key", regex: /Battle\.[a-z0-9_]+/i },
    { name: "undefined_ms", regex: /undefined\s*ms/i },
  ];

  const hits = patterns.filter((p) => p.regex.test(text)).map((p) => p.name);

  return {
    ok: hits.length === 0,
    hits,
    snippet: hits.length > 0 ? text.slice(0, 300) : null,
  };
})();
```

## 4. /battle 画面共通ルール（プレイヤーネーム表示）

すべてのバトル画面（ロビー、アリーナ、VSバッジ、HPバー、結果モーダル、ラウンドログモーダル）において、以下の名前表示ルールが厳格に守られていることを検証します。

1. **自身の表示**:
   - プレイヤーAの画面: 自身の枠は名前を表示せず、**"YOU"** と表示する。
   - プレイヤーBの画面: 自身の枠は名前を表示せず、**"YOU"** と表示する。
2. **相手の表示**:
   - プレイヤーAの画面: 対戦相手の枠は**プレイヤーBの実名**を表示する。
   - プレイヤーBの画面: 対戦相手の枠は**プレイヤーAの実名**を表示する。
3. **観戦者の表示**:
   - 観戦者画面: プレイヤーAの枠は**プレイヤーAの実名**、プレイヤーBの枠は**プレイヤーBの実名**を表示する。
   - 観戦者待機リスト: 自身は **"YOU"**、他の観戦者は**実名**を表示する。

## 5. 試合中挙動・同期確認における20戦試行ルール（必須）

試合中の挙動確認フェーズ（同期確認、HP減少、ダメージ計算、ラウンド遷移、フライング、リロード離脱など）の精度を上げるため、本スキル実行による動作確認依頼時は**以下の試行ルールを厳格に適用**します。

1. **試行回数は最低20戦（20マッチ）実施すること**:
   - 単発の1戦・1ラウンドの確認で終了せず、連続して試合・再戦を行い、**計20戦**の試合を完遂すること。
   - ホスト・ゲスト間の再戦（`onRequestRematch` / `onReturnToLobby`）、観戦者昇格後の対戦などを含めて連続試行する。
2. **20戦中に一度でも不具合が認められた場合は不具合としてカウント**:
   - 20戦の試行中に、同期ズレ（HPやタイマーの不一致）、勝敗判定の誤り、フライング時の不正値露出、表示崩れ、`undefined`/`null`/`NaN`の混入、切断・昇格時の不整合が**1回でも**発生した場合は、直ちに不具合としてカウントし、調査メモに記録すること。
   - 19戦正常でも1戦失敗した場合は、そのテストケースの結果は **「×」** とする。

## 6. 重点テストケース体系

### カテゴリ 1: 環境・デバイス設定＆PC/モバイル混在検証 (TC-ENV)

- **TC-ENV-01: デバッグChrome起動確認**
  - ポート9235の疎通確認。未起動時は起動スクリプトを実行。
- **TC-ENV-02: 端末（タブ）管理**
  - タブ1（Host）、タブ2（Guest）、タブ3（Spectator）を識別・選択できること。
- **TC-ENV-03: PC/モバイル混在マトリクステスト**
  以下の6パターンすべてで対戦ルームへ入室し、表示と動作を検証する。
  1. `Host: Mobile` / `Guest: Mobile` / `Spectator: Mobile`（全員モバイル）
  2. `Host: PC` / `Guest: PC` / `Spectator: PC`（全員PC）
  3. `Host: Mobile` / `Guest: PC` / `Spectator: PC`（ホストだけモバイル）
  4. `Host: PC` / `Guest: Mobile` / `Spectator: Mobile`（ホストだけPC）
  5. `Host: PC` / `Guest: PC` / `Spectator: Mobile`（観戦者だけモバイル）
  6. `Host: Mobile` / `Guest: Mobile` / `Spectator: PC`（観戦者だけPC）
  - **検証基準**:
    - デバイス不一致時（Mobile vs PC）に対戦開始時 `DEVICE_WARNING` モーダルが正常に表示され、両者承諾で対戦に進めること。
    - 各画面の端末アイコン（`Smartphone` / `Monitor`）が、各プレイヤーの実際の端末タイプと全画面で一致していること。

### カテゴリ 2: ロビー・接続・部屋最大人数上限 (TC-LOB)

- **TC-LOB-01: 部屋作成とルームコード発行**
  - ホストが名前入力、初期HP（500〜3000ms）を選択して部屋を作成し、6桁コードが発行されること。
- **TC-LOB-02: 招待コード入室・Player 2枠確定**
  - ゲストがコードと名前を入力して入室し、Player 2枠としてマッチングされること。
- **TC-LOB-03: 観戦者入室・Spectatorロール割当**
  - 3人目が同一コードで入室した際、自動的に `SPECTATOR` が割り当てられ、「待機順位: 1番目」が表示されること。
- **TC-LOB-04: 部屋最大人数（MAX_ROOM_PARTICIPANTS = 6）上限検証**
  - 計6名（Player 2名 + Spectator 4名）が満室まで正常に入室できること。
  - プレイヤー画面で「待機中: 4名」と全観戦者リストが正しく同期されること。
- **TC-LOB-05: 7人目の入室拒否・ROOM_FULL エラー表示**
  - 6名満員の部屋に7人目が参加を試行した場合、APIが 409 `ROOM_FULL` を返し、UI上に「この部屋は満員です (`room_full`)」が表示され入室が拒否されること。
- **TC-LOB-06: 満員からの退室による枠空き・再参加検証**
  - 満員（6名）から観戦者1名が退室（リロード等）した場合、人数が5名に減り、新たな参加者が正常に入室できること。
- **TC-LOB-07: HP初期設定（500〜3000ms）の同期**
  - ホストが初期HPを変更した際、ゲストおよび全観戦者の画面ヘッダー/HPバーに即時反映されること。
- **TC-LOB-08: プレイヤー名バリデーション**
  - 15文字制限、前後空白トリム、空欄時の自動名（Guest_xxxx）割り当てが正しく機能すること。

- **TC-SPC-04: 複数観戦者時のキュー順序管理（FIFO）**
  - 待機順位が昇格・離脱時に正しく繰り上がること。
- **TC-SPC-05: 試合進行中の観戦者「途中参加（Late Join）」検証（新設）**
  - 対戦進行中（ラウンド2以降進行中）に新たな観戦者がルームコードまたは招待リンクで入室した際、現行ラウンド番号、現在HP、過去ラウンドログ、待機順位が最新スナップショットから正しく同期され、進行中の対戦に安全に途中合流できること（HPの巻き戻りやクラッシュがないこと）。

### カテゴリ 8: リロード離脱・自動昇格・途中退出表示 (TC-REL)

- **TC-REL-01: リロード即時離脱＆枠解放検証（重要）**
  - プレイヤーまたは観戦者がリロードを実行した時点で即座に部屋から抜けた判定となること。
  - リロード完了して名前入力画面（BattleLobbyModal）が表示された状態で、他クライアント側の参加人数カウントが即座にデクリメントされ、部屋の参加枠が解放されていること（参加状態が残っていないこと）。
- **TC-REL-02: 試合中のプレイヤーリロードによる即時決着と表示検証**
  - 試合中にリロードされた場合、即座に試合終了（`opponent_left`）。
  - **残った側**: 結果画面に「相手が退出しました (`match_win_opponent_left`)」が正常表示され、「undefinedが退出しました」等の不正文字列が出ないこと。
  - **観戦者**: 結果画面に「対戦相手が退出しました (`spectator_result_opponent_left`)」が表示され、勝敗カードやHPが正常であること。
- **TC-REL-03: 試合後ロビー復帰時のホスト昇格＆観戦者のプレイヤー昇格（重要）**
  - 残ったプレイヤーが結果画面で「ロビーに戻る」を押下。
  - **残ったプレイヤー**: 自動的に「ホスト（PLAYER_1 / isGameHost）」に昇格し、HP変更や対戦開始権限を保持すること。
  - **観戦者A**: 自動的に「プレイヤー（PLAYER_2）」に昇格し、待機順位表示から対戦プレイヤーUIへ切り替わること。
  - **次戦開始確認**: 新ホストが「対戦開始」を押下し、昇格した新プレイヤーと正常に次戦が開始できること。
- **TC-REL-04: ロビー待機中のプレイヤーリロード離脱と昇格**
  - ホストリロード時はゲストがホストに昇格し観戦者がゲストに昇格、ゲストリロード時は観戦者がゲストに昇格すること。
- **TC-REL-05: 観戦者のリロード離脱と待機枠解放**

### カテゴリ 9: 部屋解散・無効/終了済み部屋への参加拒否 (TC-LIF)（重要・新設）

- **TC-LIF-01: ホストによる明示的部屋解散と全参加者退出**
  - ホストが解散ボタン（`RoomDissolveConfirmationModal`）から部屋を解散した際、サーバー側で部屋ステータスが `ENDED` に更新されること。
  - 参加中のゲストおよび全観戦者に解散イベントが即座に配信され、進行中の対戦・待機が中断されて全員がトップ/ロビーへ復帰すること。
  - 解散時に誤った勝敗や戦績が記録されないこと。
- **TC-LIF-02: 解散済み部屋（終了済みルーム）へのコード参加拒否検証（重要）**
  - 解散済みの部屋コード（`room.status === "ENDED"`）を入力して入室を試行した場合、APIが 410 `ROOM_ENDED` を返すこと。
  - UI上に「この対戦部屋は終了したか、存在しません (`room_invalid`)」のアラートが表示され、参加が拒否されてロビーに留まること。
  - 空のRealtimeチャンネルへの誤接続や幽霊部屋化が発生しないこと。
- **TC-LIF-03: 解散済み部屋への共有リンク（?room=...）直接アクセス拒否検証**
  - 解散済みのURL（`?room=XXXXXX`）をブラウザで直接開いた場合、サーバー検証で弾かれ、終了通知が表示されてトップまたはロビーへ戻されること。
- **TC-LIF-04: 存在しない無効ルームコード（ROOM_NOT_FOUND）の参加拒否検証**
  - ランダムな無効コード（例: `000000`）での参加試行時にも同様にエラー通知が表示され、入室がブロックされること。

### カテゴリ 10: ネットワーク・競合・多言語・オーディオ (TC-ADV)

- **TC-NET-01: バックグラウンド化・タブ復帰（Page Visibility）検証**
  - 試合進行中またはロビー待機中に別タブへ切り替えて非アクティブ（バックグラウンド）にした後、再度タブをアクティブに戻した際、WebSocket（Realtime）接続が維持され、最新の状態に即時キャッチアップされること。
- **TC-I18-01: 多言語混在（ja ⇄ en）対戦検証**
  - プレイヤーAが日本語（`/ja/battle`）、プレイヤーBが英語（`/en/battle`）で入室した場合に、各画面で自画面（言語設定によらず「YOU」統一）、相手名、勝敗・システムメッセージがそれぞれの言語設定に従って正しく表示されること。
- **TC-CLI-01: 招待リンク（URLクエリ `?room=...`）経由の直接参加検証**
  - ホスト画面の「招待リンクコピー」機能、およびURLパラメータ付きリンクでアクセスした際に入室前名前確認モーダルが正常に表示され、確定後に正規のロールで参加できること。
- **TC-CON-01: 並行操作・競合（Race Conditions）防止検証**
  - 試合終了時に両プレイヤーが同時に「観戦者になる」を押下した場合、または同時に「再戦」を押下した場合に、二重昇格やロック状態にならず整合性が保たれること。
- **TC-SND-01: 音声ミュートトグルおよびオーディオ再生安定性検証**
  - 各画面で音量ミュートトグル（Volume2 / VolumeX）が機能し、ミュート状態でもタップ効果音やGodlike再生時にJS例外が発生しないこと。
